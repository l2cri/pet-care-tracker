# 02: Доменное ядро — даты и срочность

**What to build:** Чистое календарное ядро: по пункту ухода и его журналу выполнений вычисляется «следующий раз» и срочность (просрочено / скоро ≤ 7 дней / спокойно). Всё покрыто юнит-тестами — это функции, на которых потом работают таймеры дашборда. Модуль не знает о React, DOM и localStorage.

**Blocked by:** 01 (Скаффолд и деплой).

**Status:** done

- [x] Типы шести сущностей модели + интервал `{value, unit: days|weeks|months|years}`
- [x] Арифметика дат `'YYYY-MM-DD'`: сложение интервалов, клампинг 31-го числа (31 января + 1 месяц), високосный февраль
- [x] `nextDue` выводится из последней записи журнала; пустой журнал = «пора сейчас» (overdue) — принятое поведение по умолчанию
- [x] Классификация срочности overdue / soon / calm; границы 6/7/8 дней протестированы
- [x] Сортировка общего списка дел по дате, бейдж карточки = самый срочный пункт подопечного
- [x] Тесты запускаются в CI

## Замечания ревью (P3/P4, не блокируют мерж)

Ревью-проход Standards/Spec по ветке `t/02-domain-dates-urgency` против merge-base с
master (`cad9a9c`): P1/P2 отсутствуют, тесты 34/34, `tsc -b` чистый.

- **P3 (Standards)** `dates.ts`: проверка «месяц 1–12, день ≤ daysInMonth» продублирована
  в `parseDate` и `toDateString` — кандидат на общий `assertValidParts`.
- **P3 (Spec)** `urgency.ts`: общий список дел сортируется по рангу срочности, затем по
  дате. Из-за монотонности ранга это совпадает с порядком «по дате» везде, кроме ничьей
  «пора сейчас» (ключ сортировки — сегодня) против пункта с due = сегодня: без журнала
  идёт раньше. Добавленная семантика задокументирована в док-комменте `sortTodoList`.
- **P4**: `withUrgency` вычисляет `nextDue` дважды (прямо и внутри `urgencyOf`) — при
  масштабе MVP несущественно.
- **P4**: трактовка «пора сейчас» живёт в `urgency` (`nextDue === null`); будущие
  потребители (DTSTART в .ics тикета 06, таймеры дашборда) обязаны обрабатывать `null` —
  учесть при проектировании тех тикетов.
- **P4**: тест-хелпер `dueIn(id, _nextDueInDays)` — параметр-документация не
  используется, та же информация есть в комментариях теста.
- **P4**: тройка `(items, log, today)` ходит через API срочности — собирать в
  контекст-тип пока преждевременно (само было бы Speculative Generality), заметка на
  будущее.
