# 02: Доменное ядро — даты и срочность

**What to build:** Чистое календарное ядро: по пункту ухода и его журналу выполнений вычисляется «следующий раз» и срочность (просрочено / скоро ≤ 7 дней / спокойно). Всё покрыто юнит-тестами — это функции, на которых потом работают таймеры дашборда. Модуль не знает о React, DOM и localStorage.

**Blocked by:** 01 (Скаффолд и деплой).

**Status:** ready-for-agent

- [ ] Типы шести сущностей модели + интервал `{value, unit: days|weeks|months|years}`
- [ ] Арифметика дат `'YYYY-MM-DD'`: сложение интервалов, клампинг 31-го числа (31 января + 1 месяц), високосный февраль
- [ ] `nextDue` выводится из последней записи журнала; пустой журнал = «пора сейчас» (overdue) — принятое поведение по умолчанию
- [ ] Классификация срочности overdue / soon / calm; границы 6/7/8 дней протестированы
- [ ] Сортировка общего списка дел по дате, бейдж карточки = самый срочный пункт подопечного
- [ ] Тесты запускаются в CI
