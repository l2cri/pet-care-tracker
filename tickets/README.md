# Таск-менеджер «Питомцы и дом»

Локальная доска тикетов: один файл на тикет, нумерация в порядке зависимостей
(блокаторы раньше заблокированных). Внешний трекер не настроен — если появится
(GitLab Issues и т.п.), тикеты переносятся туда с сохранением blocking edges.

## Как работать

- Назначение по агентам команды (domain-core / storage-state / ui-craft /
  qa-acceptance) — в [docs/AGENTS.md](../docs/AGENTS.md), таблица «Владение тикетами».
- **Фронт работ** = тикеты, у которых все тикеты из «Blocked by» закрыты **и смержены**
  в master. Первый тикет — [01](01-scaffold-and-deploy.md), он не заблокирован ничем.
- Начинаете тикет — меняйте `Status: ready-for-agent` на `Status: in-progress`
  (работа идёт в своём worktree — см. [docs/WORKFLOW.md](../docs/WORKFLOW.md)).
- Закончили — на `Status: done` и отметьте галочки критериев приёмки.
- **Done — ещё не мерж**: сначала ревью-сессия code-review в новом окне и правка
  P1/P2, затем MR в GitLab — и человек сливает его со сквошем в master.
- Каждый тикет — вертикальный срез: проходит через ядро и UI и демонстрируется сам
  по себе. Никаких «слоёных» тикетов «сделать все компоненты».
- Термины — из [GLOSSARY](../docs/GLOSSARY.md), решения — из [SPEC](../docs/SPEC.md)
  и [ADR](../docs/adr/). Тикет им противоречить не должен; если нашли противоречие —
  правьте документ, потом тикет.
