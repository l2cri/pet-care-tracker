# Архитектура: Питомцы и дом

## Общий принцип

Три слоя с жёстким правилом зависимостей (стрелка = «может импортировать»):

```
app (React: экраны, компоненты, стор, стили)
 │
 ▼
storage (репозиторий над localStorage, JSON-бэкап)
 │
 ▼
domain (чистое ядро: типы, даты, срочность, .ics, графики, демо-данные)
```

- **`domain` не знает ни о React, ни о DOM, ни о localStorage.** Это чистый TypeScript с функциями «вход → выход». Весь сложный смысл проекта (календарная арифметика, .ics, срочность, нормализация графиков) живёт здесь.
- **`storage`** прячет localStorage за интерфейсом репозитория и умеет сериализовать/десериализовать всё состояние в JSON с `formatVersion`.
- **`app`** — React: стор на context + useReducer, два экрана, компоненты, CSS Modules. Никакой бизнес-логики: только вызывает функции `domain` и пишет экшены в стор.

Такая композиция — прямое следствие решений [ADR-0001](adr/0001-local-first-no-backend.md) (local-first), [ADR-0003](adr/0003-completion-log-as-source-of-truth.md) (выводимость дат) и [ADR-0005](adr/0005-hand-rolled-svg-charts.md) (свои графики): почти вся ценность — вычисления, поэтому ядро выделено в тестируемый слой без инфраструктуры.

## Дерево каталогов

```
src/
  domain/                 # чистое ядро (единственный высокий шов тестов)
    model.ts              #   типы шести сущностей + AppState
    dates.ts              #   'YYYY-MM-DD' арифметика: сложение интервалов,
                          #   nextDue(item, log), daysUntil
    urgency.ts            #   классификация overdue / soon / calm, сортировки дашборда
    ics.ts                #   buildIcs(...) → строка VCALENDAR (RRULE, VALARM, folding)
    charts.ts             #   weightLineChart(entries, viewBox) → геометрия линии
                          #   (столбики расходов добавит тикет 09)
    presets.ts            #   пресеты ухода (прививки 12 мес, паразиты 3 мес, груминг 2 мес)
    demoData.ts           #   демо-набор: 2 питомца с историей
  storage/
    repository.ts         #   интерфейс Repository (load / save / wipe)
    localStorageRepo.ts   #   тонкая обёртка над localStorage
    backup.ts             #   конверт { formatVersion, state }: export/import
                          #   с валидацией и миграциями по formatVersion
                          #   (конверт общий с localStorage)
  app/
    store.tsx             #   context + useReducer + автосохранение в репозиторий
    screens/
      Dashboard/          #   карточки подопечных + общий список «просрочено/скоро»
      PetCard/            #   вкладки Уход / Вес / Корм
    components/           #   PetCard, CareTimer, UrgencyBadge, BottomSheet,
                          #   WeightChart (SVG), SpendBars (SVG), IcsButton, PhotoInput
  styles/
    tokens.css            #   дизайн-токены: палитра (light/dark), радиусы, отступы
```

## Ключевые потоки

**Клик «Сделано».** Компонент диспатчит экшен `logCompletion(careItemId, date, note?)` → reducer добавляет `CompletionLogEntry` → стор сохраняет состояние через репозиторий → все таймеры на дашборде перерисовываются, потому что `nextDue` — вычисляемое из лога, а не хранимое поле.

**Экспорт .ics.** `domain/ics.ts` получает пункт ухода (или разовое событие) и вычисленную дату следующего выполнения, возвращает строку VCALENDAR. Единственная DOM-операция — обёртка в Blob и клик по временной ссылке — живёт в `app` и остаётся за пределами ядра, чтобы `ics.ts` тестировался чистым вызовом функции.

**График веса.** `domain/charts.ts` превращает список замеров в нормализованные координаты внутри заданного viewBox (автоскейл по min/max, защитные поля, вырожденные случаи «пусто/одна точка/все равны»). React-компонент только отображает готовую геометрию и ловит тап по точке для тултипа.

**Бэкап.** `storage/backup.ts` сериализует всё состояние в JSON c `formatVersion`; импорт валидирует и применяет. Фото уже dataURL — отдельной обработки не нужно.

## Швы тестирования

Приоритет — минимальное число швов, максимально высоких:

1. **`domain/` — главный шов.** Чистые функции без моков: гоняем `nextDue` по границам (високосный февраль, 31-е числа, смена интервала), `buildIcs` сверяем со эталонными строками, `normalize` — по вырожденным данным.
2. **`Repository` — второй шов.** Интерфейс с двумя реализациями: in-memory (для тестов round-trip экспорт/импорт и reducer-логики) и localStorage (тонкая, почти не тестируемая обёртка).

UI не тестируем в MVP ([спека, Testing Decisions](SPEC.md)). Новые швы добавляются только если этих двух перестало хватать — сначала предложить расширение этих.

## Что сознательно отсутствует

Роутер (два экрана, навигация стейтом — [ADR-0006](adr/0006-stack-and-styling.md)); UI-библиотека и Tailwind (токены + CSS Modules); чартовая библиотека ([ADR-0005](adr/0005-hand-rolled-svg-charts.md)); PWA и Notification API ([ADR-0004](adr/0004-ics-export-instead-of-push.md)); бэкенд ([ADR-0001](adr/0001-local-first-no-backend.md)).

## Когда архитектуре понадобится эволюция

- **Итерация 2 («дом»):** новые типы подопечных включаются без изменений схемы — `CareSubject.type` уже различает pet / item / plant ([ADR-0002](adr/0002-universal-care-subject-model.md)); на дашборде добавится секция «Дом».
- **Много фото / больших данных:** замена localStorage на IndexedDB — точечная: меняется реализация `Repository`, `domain` и `app` не замечают.
- **Синхронизация между устройствами:** появляется третий репозиторий (серверный), ядро не трогаем.
