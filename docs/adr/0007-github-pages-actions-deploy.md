# ADR-0007: Деплой на GitHub Pages через GitHub Actions

**Статус:** Частично заменён ADR-0009 (2026-10-24): репозиторий и деплой переехали в GitLab — MR со сквошем, GitLab CI, GitLab Pages. Сам принцип `base`-пути и статического деплоя живёт дальше там. Ниже — исходная формулировка для истории.

**Статус (исходный):** Принято (2026-10-24). Выбор площадки изменён пользователем в ходе интервью (первоначальная рекомендация Vercel отклонена).

## Контекст

Нужен бесплатный статический хостинг с автодеплоем, без отдельной учётки ещё в одном сервисе. Vite-приложение на GitHub Pages живёт на поддомене пути (`username.github.io/<repo>/`), из-за чего дефолтные абсолютные пути ассетов ломаются — нужен `base`. У Vercel этой проблемы нет, но выбран GitHub Pages: всё в одной экосистеме с кодом.

## Решение

GitHub Pages, публикация через **GitHub Actions**: workflow собирает Vite-билд на push в main и деплоит артефакт штатным Pages-действием. В конфиге Vite задаётся `base: '/<имя-репо>/'`. Ручная ветка `gh-pages` не используется.

## Последствия

- (+) Один сервис для кода и сайта; деплой — просмотримый workflow-файл в репозитории (тоже часть портфолио-кейса).
- (+) Бесплатно и без сборки на локальной машине.
- (−) Не забыть `base`-путь — классическая ловушка, зафиксировано здесь и в тикете скаффолда.
- (−) Пользовательский домен и HTTPS-сертификаты — вне MVP; при переезде на свой домен `base` меняется на `/`.
