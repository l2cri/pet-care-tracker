# ADR-0008: Гигиена данных — локальные даты 'YYYY-MM-DD' и целые граммы

**Статус:** Принято (2026-10-24)

## Контекст

Календарная арифметика и экспорт в календарь — главные источники тихих багов: таймзоны, летнее время, float-погрешности при сложении килограммов. Приложение оперирует «датами без времени» (прививка — это день, а не момент), а вес в килограммах — типичное место для `4.1 + 0.2`-артефактов.

## Решение

- Все даты в домене, хранилище и UI — **локальные строки `'YYYY-MM-DD'`**. Никаких `Date`-объектов в состоянии, никакого UTC-преобразования: парсим и складываем как календарные даты. Это же делает тривиальным all-day VEVENT в .ics (`DTSTART;VALUE=DATE`).
- Вес хранится **целым числом граммов** (`WeightEntry.grams: number`, целое). Килограммы — только форматирование на выводе.
- Идентификаторы сущностей — `crypto.randomUUID()`, экспортный JSON несёт `formatVersion`.

## Последствия

- (+) Таймзонные баги исключены по построению; тесты дат — чистая календарная арифметика (31 января + 1 месяц, високосный февраль).
- (+) Целые граммы дают точную арифметику и сравнимость; форматирование в кг — одна функция.
- (−) Соблазн «просто возьму `new Date()`» придётся пресекать код-ревью; в `domain/dates.ts` единая точка входа для работы с датами.
- (−) Ввод даты в UI требует аккуратного парсинга (високосные, границы месяцев) — покрыто тестами форм-валидации.
