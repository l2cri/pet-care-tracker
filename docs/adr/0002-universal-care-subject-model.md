# ADR-0002: Универсальная модель «подопечный» при pet-only UI в MVP

**Статус:** Принято (2026-10-24)

## Контекст

Идея проекта охватывает и питомцев, и «дом» (фильтры для воды, полив капризных растений). Но у фильтра нет веса и прививок, а у кота нет «полива» — наивное объединение UI раздувает первую версию и распыляет 2–3 недели вечеров. При этом механика заботы одинакова: «сделал X, следующий раз через N дней».

## Решение

Схема данных с первого дня универсальная: сущность **Подопечный** (`CareSubject`) с полем `type`: 'pet' | 'item' | 'plant'. Пункты ухода, лог выполнений, разовые события привязываются к подопечному любого типа. UI MVP затачивается только под питомцев; «дом» появляется второй итерацией как новая секция дашборда — без миграции схемы.

## Последствия

- (+) Итерация 2 — это UI-работа, а не рефакторинг данных.
- (+) Дешёвая страховка от «а добавь ещё аквариум/фильтр-и-кошку».
- (−) Поле `type` в MVP почти не используется — осознанно платим небольшим заделом на будущее, о котором честно сказано в спеке.
