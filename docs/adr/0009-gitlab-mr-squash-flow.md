# ADR-0009: Разработка и деплой через GitLab — MR со сквошем и GitLab Pages

**Статус:** Принято (2026-10-24). Заменяет ADR-0007 (деплой-часть: GitHub Actions/GitHub Pages → GitLab CI/GitLab Pages).

## Контекст

Владелец работает с кодом в GitLab и хочет лично контролировать попадание изменений
в master: принимать MR-ы и сливать их самому, одним кнопочным действием. Флоу
«worktree + сессия на тикет» уже принят (docs/WORKFLOW.md); встал вопрос о форме
мержа (локальный `--no-ff`, PR/MR без сквоша, MR со сквошем) и о площадке деплоя,
которая была привязана к GitHub.

## Решение

- **Репозиторий — GitLab**, ветка по умолчанию **master**, защищена от прямых пушей.
- **Мерж — только MR со включённым squash**: тикет-сессия пушит ветку `t/NN-slog`,
  штаб открывает MR `#NN: <название>`, после ревью-сессии code-review человек жмёт
  Merge. В master попадает ровно один коммит на тикет; пошаговая история сессии
  остаётся в MR.
- **CI — GitLab CI**: `npm ci` + vitest на каждый пуш в ветки и master; деплой
  статикой на **GitLab Pages** из master (та же идея, что была в ADR-0007:
  публичный URL под-path проекта, поэтому в Vite задаётся `base: '/pet-care-tracker/'`).

## Последствия

- (+) Человек — единственная точка слияния: ничего не попадает в master без явного
  нажатия Merge; сквош-коммиты `#NN: …` дают читаемый журнал вех.
- (+) Ревью-сессия code-review + зелёный CI в ветке — гейт до передачи MR человеку.
- (+) GitLab Pages деплоится той же CI без второго сервиса и токенов.
- (−) Пошаговая история «как думала сессия» не попадает в master — она сохраняется
  в MR и чек-боксах тикета; осознанный размен.
- (−) Классическая ловушка под-path-хостинга остаётся из ADR-0007: не забыть `base`
  (зафиксировано в тикете 01); при переезде на свой домен `base` меняется на `/`.
