# ADR-0009: Слияние через GitHub PR со сквошем

**Статус:** Принято (2026-10-24). Дополняет ADR-0007 (деплой GitHub Pages через Actions); мерж-флоу — этот ADR.

## Контекст

Владелец хочет лично контролировать попадание изменений в master: принимать пул-реквесты и сливать их самому, одним кнопочным действием. Флоу «worktree + сессия на тикет» уже принят (docs/WORKFLOW.md); встал вопрос о форме мержа (локальный `--no-ff`, PR без сквоша, PR со сквошем). Репозиторий: github.com/l2cri/pet-care-tracker, ветка по умолчанию master.

## Решение

- **Мерж — только PR со включённым squash**: тикет-сессия пушит ветку `t/NN-slog`, штаб открывает PR `#NN: <название>`, после ревью-сессии code-review человек жмёт «Squash and merge». В master попадает ровно один коммит на тикет; пошаговая история сессии остаётся в PR.
- **Master без прямых пушей**: защита ветки в настройках репозитория; в Settings единственный разрешённый метод слияния — squash.
- CI (GitHub Actions) и деплой (GitHub Pages из master) — по ADR-0007 и тикету 01.

## Последствия

- (+) Человек — единственная точка слияния: ничего не попадает в master без явного нажатия; сквош-коммиты `#NN: …` дают читаемый журнал вех.
- (+) Ревью-сессия code-review + зелёный CI в ветке — гейт до передачи PR человеку.
- (−) Пошаговая история «как думала сессия» не попадает в master — она сохраняется в PR и чек-боксах тикета; осознанный размен.
- (−) Настройка защиты ветки и метода слияния — ручной шаг владельца в Settings (чек-бокс в WORKFLOW.md → Bootstrap).
