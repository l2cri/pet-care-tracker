# ADR-0004: Напоминания через .ics-экспорт вместо push

**Статус:** Принято (2026-10-24)

## Контекст

Приложение без бэкенда обязано ответить на вопрос «как я узнаю, что пора колоть прививку, если приложение закрыто?». Варианты: Notification API (требует открытой вкладки/сервис-воркера), PWA с push (нужен сервер для рассылки), интеграция с системным календарём. При этом пользователь уже живёт в календаре телефона, и повторяющиеся события календарь умеет сам.

## Решение

Канал напоминаний — **экспорт .ics прямо в браузере**: чистый строковый шаблон → Blob → скачивание → календарь телефона подхватывает файл. Повторяющиеся пункты ухода — all-day VEVENT с `RRULE` (FREQ/INTERVAL выводится из интервала пункта) и `VALARM` за сутки; `DTSTART` — вычисленная дата следующего выполнения. Разовые события — одиночное VEVENT. Никаких библиотек: генератор — самописный модуль ядра. Notification API и PWA в MVP не делаем; installable PWA — кандидат в итерацию 2.

## Последствия

- (+) Напоминания работают «в кармане» без сервера, без разрешения на уведомления, без service worker.
- (+) Самописный генератор .ics (экранирование, folding длинных строк, RRULE) — сильная портфолио-фиича с честными юнит-тестами.
- (+) All-day события и локальные даты `'YYYY-MM-DD'` полностью снимают таймзонные сюрпризы.
- (−) Экспорт — ручное действие пользователя: добавил пункт — выгрузил событие. Проговариваем в UI (иконка календаря у пункта).
- (−) Если пользователь меняет интервал пункта, старое событие в календаре придётся удалить руками — честно пишем в README.
